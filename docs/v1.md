# MT Exec Bridge v1.0（一代）

> 状态：**已存档**，被 [v2.x](v2.md) 取代。本文保留供历史参考；仍在运行 v1 的设备建议升级（升级指引见文末）。

## 设计概览

v1 的全部逻辑只有一句话：**守护进程 300ms 轮询单个命令文件 `in/cmd.sh`，出现即以 root 执行，输出与退出码写 `out/result.txt`。**

```
KSU service.sh (uid=0, u:r:ksu:s0)
 └─ execd (C，仅依赖 bionic libc)
     ├─ fopen in/cmd.sh → fread → unlink（先删防重复执行）
     ├─ popen("<命令> 2>&1", "r")
     └─ 输出 + exit code 写 out/result.txt
```

模块侧：

- `service.sh`：开机初始化目录 + `chmod 0700` + `nohup` 拉起 execd；二进制缺失时跑 `polld.sh`（1s shell 轮询兑底）
- `action.sh`：KSU 管理器「执行」按钮，手动处理一次 cmd.sh
- `customize.sh`：安装时配置权限（脚本 755、目录 0700）

## 任务格式

无首行指令体系。`cmd.sh` 内容即 sh 命令，可多行，stderr 自动合并。

结果格式：

```
=== <epoch> ===
<stdout + stderr>
=== exit N ===
```

## 已知局限（全部在 v2.0 修复）

| 局限 | 后果 | v2.0 对应修复 |
|---|---|---|
| 单命令文件，无队列 | 多客户端同窗口写入互相覆盖，命令丢失 | `in/*.sh` 队列 |
| 16KB 静默截断 | 超长脚本尾部丢失，执行残缺脚本 | 动态读取，8MB 上限 + 拒收隔离 |
| 无超时保护 | 一条挂起命令永久卡死整个桥 | fork + setpgid + 看门狗击杀 |
| 输出无上限 | `cat 大文件` 撑爆存储 | 8MB 截断标注 |
| 结果非原子发布 | 读者可能读到半截输出 | `.tmp + rename` |
| 无审计 | 无法追溯谁执行了什么 | `history.log` |
| 无单实例/自愈 | 重复拉起或死亡后无人接管 | `flock` + `supervisor.sh` |
| 环境裸 | PATH/HOME/TMPDIR 需每条命令手动设置 | `env.sh` 持久环境 |
| 长任务阻塞全队 | 后续命令全部排队等待 | `#!async` 异步任务 |

## 升级指引（v1 → v2）

1. 直接刷入 v2.x zip（同 id 自动升级），重启
2. 协议变化：直接写 `cmd.sh` 仍然兼容（v2 把它视为普通队列文件），但推荐改用「临时文件 + 原子 rename → `in/job-*.sh`」
3. 命令首行可加 `#!timeout=N` / `#!async`
4. 查看 `out/history.log` 确认新守护进程已接管
