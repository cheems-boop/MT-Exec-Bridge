# MT Exec Bridge v2.x（二代）技术文档

> 面向想读懂/改造 `execd.c` 的贡献者，以及需要精确协议语义的调用方开发。
> 快速上手请看 [README](../README.md)；一代存档见 [v1.md](v1.md)。

## 1. 文件接口规范

### 1.1 任务目录 `in/`（0700）

| 路径 | 语义 |
|---|---|
| `in/job-<epoch>.sh` | 任务文件：守护进程扫描所有 `*.sh`，**按字典序**依次执行，执行后删除 |
| `in/cmd.sh` | v1 兼容入口：等价于普通任务文件（`c` 字典序最先，天然优先执行） |
| `in/env.sh` | 持久环境变量，每个任务执行前被 source；被排除在任务扫描之外 |
| `in/.*` | 隐藏文件被忽略 —— 客户端临时文件建议用 `.` 前缀 |

### 1.2 结果目录 `out/`（0700）

| 路径 | 语义 |
|---|---|
| `result.txt` | 最近一次同步任务的完整输出（原子发布） |
| `history.log` | 审计追加日志；超 4MB 轮转为 `history.log.1` |
| `<任务名>.log` | `#!async` 任务的独立日志 |
| `rejected_<名>` | 拒收隔离：超 8MB / 读取竞态 / 空文件 |
| `execd.pid` / `execd.lock` | 守护进程 pid 与 flock 锁文件 |

### 1.3 结果格式

```
=== <人类时间> (<epoch>) | job: <文件名> ===
<stdout + stderr（合并，8MB 处截断并标注）>
=== exit N | <耗时>ms ===
```

超时终止：

```
=== TIMEOUT after Ns (process group killed) ===
```

审计行格式：

```
<人类时间> | <任务名> | uid=<writer_uid> | <耗时>ms | exit=<N> | out=<字节>B | <命令首行，去换行，≤160字符>
```

## 2. 任务生命周期

```
写入 .tmp ──rename──▶ in/job-*.sh
                        │ 200ms 扫描周期
                        ▼
              opendir + qsort 字典序
                        │
     fstat 尺寸预检(≤8MB) → fread 全量 → fgetc 竞态检测
                        │ 失败 → 拒收隔离 + ERROR 结果 + 审计
                        ▼
          解析首行指令(#!timeout=N / #!async)
                        │
     ┌── async ─────────┴──────── sync ──┐
     │ 双 fork + setsid                   │ fork + setpgid
     │ stdout/stderr → out/<名>.log       │ /system/bin/sh -c
     │ 父进程立即返回 [ASYNC]              │ stdout/stderr → pipe(非阻塞)
     │                                    │ poll(500ms) 排空 + waitpid(WNOHANG)
     │                                    │ 超时 → kill(-pid, SIGKILL) → waitpid
     └─────────────┬──────────────────────┘
                   ▼
   footer(exit/TIMEOUT) → close → rename 原子发布
        → unlink 任务文件 → 追加审计
```

## 3. 关键实现点

### 3.1 为什么排空管道必须非阻塞（v2.1 教训）

v2.0 曾用 `while (read() > 0)` 排空阻塞管道：子进程静默时（如 `sleep`），read 无限期阻塞在排空循环内，超时检查永远不可达 —— 看门狗失效。

修复：fork 后立即 `fcntl(O_NONBLOCK)`，排空读到 EAGAIN/EOF 即止。

**设计规则：任何「读子进程输出 + 同时管超时」的实现，都必须保证单次 read 不可能无限阻塞。**

### 3.2 竞态防线（三层）

1. **客户端层**：写 `.tmp` 再 `rename()` —— 对守护进程原子可见
2. **读取层**：`fstat` 取尺寸 → `fread` → `fgetc` 探测是否还有剩余字节 —— 命中「文件增长」即拒收隔离
3. **发布层**：结果写 `.result.tmp` → `rename` —— 读者永远看不到半截结果

### 3.3 进程组超时

子进程 `setpgid(0,0)` 独立成进程组，超时 `kill(-pid, SIGKILL)` 连孙进程一起清场；父进程 `waitpid` 回收，避免僵尸。

### 3.4 双 fork 异步

`#!async` 任务 fork 两次：中间进程立即退出并被回收，孙进程 `setsid` 脱离会话由 init 收养 —— 守护进程不留僵尸，队列不被阻塞。

### 3.5 单实例

`out/execd.lock` 上 `flock(LOCK_EX | LOCK_NB)`：看门狗误拉起多份、模块反复开关，全局只会有一个守护进程存活。

## 4. 与 Termux 生态的接入

`setup_env()` 检测到 `/data/data/com.termux/files/home` 存在时：

- `HOME` → Termux home，`TMPDIR` → `$PREFIX/tmp`
- `PATH` 首位插入 `/data/data/com.termux/files/usr/bin`

配合 `in/env.sh` 写入 `LD_LIBRARY_PATH=$PREFIX/lib`，即可在 root 上下文直接调用 Termux 的 clang / ffmpeg / python 等全部工具链（实测 ffmpeg 9.0.2 转码可用）。

> 注意：用 root 身份运行 Termux 的 `apt` 会产生 root 属主文件，破坏 Termux 自身升级 —— 包管理操作请在 Termux 内亲手执行。

## 5. 性能实测参考

| 指标 | 实测值 |
|---|---|
| 端到端延迟（write→rename→执行→result 可读） | 轻任务 ~0.3s（一个扫描周期内） |
| 轮询开销 | opendir+readdir 每 200ms，CPU 可忽略 |
| `#!timeout=1` 击杀精度 | 1029ms（± 一个扫描周期） |
| clang 编译 14KB 单文件 | ~330ms |

## 6. 协议兼容性

- v1 客户端（直接写 `cmd.sh`）无需任何修改即可工作
- v2 推荐协议（`.tmp + rename → job-*.sh`）向下兼容 `cmd.sh`（字典序最先）
- `polld.sh`（shell 降级）与 execd 同目录协议；execd 缺失时 supervisor 自动启用
